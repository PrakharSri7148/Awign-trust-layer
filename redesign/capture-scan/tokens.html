AI scan step: new components

Viewer · Coverage · Gallery · Photo step tokens (all colors, type, buttons, pills…). This step adds no new color token: every color below is a Photo-step token. New CSS lives in css/scan.css and loads after the three Photo stylesheets. Everything on this page is rendered with that CSS.

Scan mark (decorative, aria-hidden)

Left to right: running · stopped (failure) · reduced motion. 56px (48px on phones). Three thin rings, one arc that turns once every 9 s, a core that fades between 100% and 62% every 2.6 s. Flat: no glow, no gradient, one hue (--cap-accent, --cap-border-2, --cap-bad).

Indeterminate bar (cap-meter--busy)

Same 20 cells as the Photo step’s overall meter (cap-meter--20), tone --cap-accent. A highlight travels along it (1.8 s loop, 70 ms offset per cell); there is no value, so no number and no fake progress. Reduced motion and stopped: static dashes (every other cell). role="progressbar" with no aria-valuenow = indeterminate; the Photo step’s role="meter" stays for values that exist.

Phones: full width inside the 12px page gutter, 12px card padding.

        Accessibility notes

        WhatHow
        Live announcementsOne role="status" aria-live="polite" aria-atomic element, visually hidden, outside the re-rendered page. Its text is replaced only when the message changes: “Step n of 5: line”, “Finishing up…”, the slow line. The list itself is not live, so no line is read twice. Failure uses role="alert" once.
        Busy statearia-busy="true" on the card while scanning; the list marks the current row with aria-current="step".
        Color is never aloneEvery row has an icon and a word; the banner has an icon and the full sentence.
        Motionprefers-reduced-motion (and the viewer’s forced html[data-motion="reduce"]): arc, core and bar stop, spinner becomes a still dot; row state changes remain.
        Touch targetsThe card has no controls. Rows are 48px tall anyway.
